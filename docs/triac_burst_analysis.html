Nebulizer Heating Analysis

不使用外部过零检测时，TRIAC_EN 应该如何分配更合适

基于当前硬件原理图，驱动器件为 MOC3063，它是 零交越导通型 光耦可控硅。结论很明确：这一路不适合相位角调功， 更适合使用 低频时间比例控制 / burst fire，即让 TRIAC_EN 在一个较慢的时间窗口内按比例开关。

先给结论： 在不使用 ZCD_OUT 的前提下，推荐先从 500 ms 控制窗口 + 50 ms 基本片段 开始。 这样既能保证零交越型器件可靠导通，也能兼顾分辨率和热惯性系统的稳定性。

为什么不能用普通高频 PWM

MOC3063 不是 MCU 看到高电平就立刻导通，它会等到交流电压经过零点附近时才动作。 因此如果 TRIAC_EN 只给很窄的脉冲，可能在这一小段时间里根本没有遇到零点， 那么这次脉冲就完全无效。

所以 kHz 级 PWM、甚至 100 Hz 的短脉冲式占空比都不合适。

为什么不需要相位角延时

相位角调功的前提是“软件精确知道过零点，然后延时若干微秒触发门极”。 但 MOC3063 本身就是零交越导通型，它会把触发时刻自动钳在零点附近。 这时软件的职责不再是“算延时”，而是“决定这一段时间是否允许导通”。

也就是：做慢速功率分配，不做快速相位控制。

为什么窗口可以做得比较慢

你的系统是“雾气经过加热管”的结构，热惯性和滞后都很大。输出功率每 10 ms 变化一次没有意义， 反而会让控制策略更难看懂、更难调试。对于这种对象，执行器层使用 200~1000 ms 级别的功率窗口反而更合适。

1. 先明确几个物理约束

  • 市电按国内常用 50 Hz 估算，一个完整周期约 20 ms，半周约 10 ms。
  • 不读取 ZCD_OUT 时，MCU 并不知道当前离下一个零点还有多久。
  • 因此一次“允许导通”的高电平，必须持续足够长，才能大概率覆盖到至少一个零点。
  • 同理，一次“禁止导通”的低电平，也应持续足够长，才能确保至少有一个零点时处于关闭状态。
工程建议： 如果完全不依赖外部过零检测，单个开/关片段最好不要短于 40~50 ms。 这相当于覆盖 2~2.5 个工频周期，容错比较舒服。

2. 几种常见分配方式对比

方案 窗口大小 最小片段 分辨率 优点 问题
快速 PWM 10~20 ms 1~5 ms 高 看起来“像 PWM” 极易错过零点，很多脉冲可能无效，不推荐
中速 burst 200 ms 40 ms 20% 响应较快，逻辑简单 分辨率偏粗，低功率附近比较跳

3. 推荐的第一版分配方式

如果现在先求稳，不考虑极致调功精度，建议第一版直接采用下面这组参数：

  • 控制窗口：500 ms
  • 基本片段：50 ms
  • 每窗口片段数：10
  • TRIAC_EN 驱动方式：在“开”的片段内持续保持高电平，在“关”的片段内持续保持低电平
  • PID 输出映射：0~1000 permille 映射为 0~10 个导通片段

4. 为什么我更推荐 500 ms，而不是更快

  • 你的被控对象是加热管 + 雾气，不是裸加热丝，热响应明显滞后。
  • 50 ms 片段已经足够覆盖多个工频周期，可靠性比 10~20 ms 更高。
  • 500 ms 对人眼、示波器、日志都比较好理解，调试直观。
  • PID 算出来就算瞬间跳动，执行器层也不会过于敏感，系统更稳。
如果后面发现 500 ms 响应太慢，可以试到 300 ms； 如果发现 功率跳变太明显，可以试到 800 ms 或 1000 ms。

5. 如何把 PID 输出映射得更细

500 ms / 50 ms 只有 10 个片段，单窗口内分辨率就是 10%。这对高延迟热系统通常已经够用， 但如果你想让 33%、37% 这种值也更平滑，可以用 跨窗口误差累计 的办法补细分辨率。

建议做法

  • 先按窗口内整数片段数做一次粗分配。
  • 不足的那一部分，用累计误差在后续几个窗口里补回来。
  • 本质上类似 sigma-delta / Bresenham 的平均化分配。

例如目标 35%：

  • 窗口 A：3 段导通 = 30%
  • 窗口 B：4 段导通 = 40%
  • 两个窗口平均下来就是 35%

6. 控制周期和执行器周期不要混在一起

即使执行器用的是 500 ms 的 burst 窗口，也不代表传感器或 PID 必须 500 ms 才算一次。 更合理的拆法是：

层级 建议周期 用途
传感器采样 20~50 ms 维持温度数据新鲜度
PID 计算 100~200 ms 避免对高延迟对象算得太快
执行器功率窗口 500 ms 决定 TRIAC_EN 的开关分配

7. 这一路最容易犯的几个错误

  • 把 TRIAC_EN 当成普通 PWM，频率设得太高。
  • 只给很窄的高脉冲，结果恰好没碰到零点，整次控制无效。
  • PID 每 20 ms 就大幅改输出，但执行器层也跟着快速抖动，导致调试上看起来很乱。
  • 没有把高延迟对象和快速驱动对象区分开，想当然地沿用直热板或风扇 PWM 的经验。

建议你先按 500 ms 窗口 / 50 ms 片段 跑第一版。如果验证后觉得温升太慢或功率太粗， 再在 300~1000 ms 之间微调窗口即可。下一步如果你确认这个方向，我可以直接把当前 Zephyr 代码改成“完全不依赖 ZCD_OUT、只按时间窗口控制 TRIAC_EN”的实现。
